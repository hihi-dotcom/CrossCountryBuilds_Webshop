API katalógus — REST végpontok

Az alábbi katalógus a feltöltött dokumentumban található végpontok és példák struktúrált megjelenítése. A dokumentum szövegét változtatás nélkül tettem be példaként (eredeti példák <pre> blokkokban).

Főoldal

Termékek lekérése a backendről — a webshop főoldal számára.

GET
/api/termekek?from=0&to=13

Leírás: Az URL-ben megjelölt két szám között található termékeket fogja visszaküldeni JSON tömb formátumban. Ezeket a frontenden tömbbe rakjuk és a webshop főoldalán jelenítjük meg.

Visszaküldött termék objektum formátuma (JSON):

[{ 
név: string

kategória: string 

gyártó: string 

leírás: string 

kép: string 

ár: number 
}
]

Szűrés eredményei a backendről

Ugyanúgy, mint a termékek elkérésénél, egyesével kérjük el a termékeket, ahol a szűrés feltételei megfelelnek a termék tulajdonságainak.

Példa a szűrés feltétel alapú kéréshez:

„/api/products/1?name=atermékneve&kategória=kategória”
Megjegyzés: a fenti URL a dokumentumban szereplő pontos példa.

Kosár — Rendelés

PUT
/api/order

A frontendről a rendelés elküldésekor a fetch kérés body-jában egy JSON objektumot kell küldeni.

Példa (küldött törzs):

{ 

products: [{product name: string, product number: number}, {product name: string, product_number: number} ], 

szállítási mód: string 

fizetési mód: string 

}

Válasz (példa):

{
state: ok || err, 

elfogyott: []string

}
Ha state = ok, átirányítás a köszönő oldalra. Ha egy termék elfogyott, a válasz tartalmazza az elfogyott listaelemeit.

Bejelentkezés

POST
/api/login

A frontenden a belépéshez használt adatokból készítünk egy rövid JSON objektumot, melyet elküldünk a backendre. A backend visszaad egy JSON objektumot, amely a bejelentkezés sikerességét mutatja.

Példa válasz objektum:

{ state: ok || err, }

Regisztráció

PUT
/api/registration

A regisztrációs adatok egy JSON objektumba tömörítve kerülnek elküldésre.

Példa regisztrációs objektum:

{ 

email: string 

name: string

password: string 

}

Példa visszaküldött state-t tartalmazó objektum:

{
 state: username is already in use || there is an account registered from this email | | ok, 
}

Saját adataim

GET
/api/user

A GET kérésre a backend egy JSON objektumot ad vissza a felhasználó adataival.

Példa a backendről kapott adatokra:

{ 

username: string 

email: string 

delivery address: string

billing address: string 

}

Módosítások (PATCH végpontok)

PATCH /api/username 
PATCH /api/email 
PATCH /api/delivery_address 
PATCH /api/billing_address 
PATCH /api/password 

Küldendő body (példa):
{ 
data: string 
} 

Válasz (példa):
{
 state: ok || err 
}

Időpontfoglalás

GET
/api/appointments

A GET kérésre a backend elküldi a behozatali időpontokat JSON objektumban.

Időpont kiválasztása és beküldése

Miután kiválasztottuk az időpontot és leírtuk a problémát, egy PATCH kérés küldendő az alábbi URL-re:

PATCH
/api/appointment

Példa küldött objektum:

{
date: string,
 description: string 
}

Példa válasz:

{
state: ok || err
}

Jelszó visszaállítás / Új jelszó

POST
/api/recovery

A POST kérés törzsében szerepel az email.

{ 
email: string 
}
PATCH
/api/recovery

Új jelszó létrehozása a PATCH kérés törzsében.

{
 password: string 
}

Admin — Termékekkel kapcsolatos műveletek

GET
/api/termekek?from=0&to=13

Ugyanaz mint a felhasználói GET: listázza a megadott tartomány termékeit.

A backendről visszaküldött termék objektum formátuma(JSON):

[
{ 

név: string 

kategória: string 

gyártó: string 

leírás: string 

kép: string 

ár: number 

}
]
PATCH
/api/admin/termek

A kérés body-ja: Kötelező elem a termék azonosítója. A többi mező megváltoztatja a termékadatokat.

Példa törzs:

{ 

name: string 

category: string 

manufacturar: string 

description: string 

picture: string 

price: number 

}
POST
/api/admin/termek

Hatás: új termék jön létre az adatbázisban (értékek nélkül).

DELETE
/api/admin/termek

Törléshez a kérés törzsében a termék nevét adjuk meg.

{
	termek_neve: „termék neve”
}

Admin — Felhasználókkal kapcsolatos műveletek

GET
/api/admin/users?from=0&to=12

Példa válasz:

[
{ 

id: number 

name: string 

szállítási cím: string 

számlázási cím: string 

email: string 

}
]
DELETE
/api/admin/users

Törléshez a body-ban küldjük a törlendő felhasználó azonosítóját:

{ id: number }

Admin — Megrendelésekkel kapcsolatos műveletek

GET
/api/admin/orders?from=0&to=12

Példa válasz (részlet a dokumentumból):

[
{ user: 

{ id: number 

name: string 

szállítási cím: sztring 

számlázási cím: string 

email: string 

} 

state: string 

items: [ 

{ name: string 

category: string 

manufacturar: string

 description: string 

picture: string 

price: number 

darabszam: number 

} 

szállítási mód: string 

fizetési mód: string 

] }]
PATCH
/api/admin/orders

Megrendelés állapotának módosítása. A kérés törzsében szerepel az azonosító és az új állapot.

{
id:number
state: string
}
DELETE
/api/admin/orders

Régi rendelés törlése, a törlendő rendelés azonosítóját kell megadni:

{ 
   id:number 
}

Admin — Időpontfoglalással (szerviz) kapcsolatos műveletek

GET
/api/admin/appointment?from=0&to=12

Példa válaszul kapott tömb:

[
{ 

id: number 

username: string 

user_email: string 

name: string 

behozatali időpont: string 

átvételi időpont: string 

description: string 

}
]
PATCH
/api/admin/appointment

Módosítás: a kérés törzsében a módosítandó tulajdonságok szerepelnek JSON objektumban.

{ 
id: number 
username: string 
user_email: string 
name: string 
behozatali időpont: string 
átvételi időpont: string 
description: string 
}
DELETE
/api/admin/apointment

Törléshez a kérés törzsében kötelező megadni az időpont azonosítóját:

{ 
id: number 
}

Gyors navigáció

Kattints a következőkre (másold a URL-t), hogy gyorsan elérd az adott végpontot a kódban vagy dokumentációban.

  • /api/termekek?from=0&to=13
  • /api/products/1?name=...
  • /api/order PUT
  • /api/login POST
  • /api/registration PUT
  • /api/user GET
  • /api/appointments GET
  • /api/recovery POST / PATCH
  • /api/admin/termek PATCH/POST/DELETE
  • /api/admin/users GET/DELETE
  • /api/admin/orders GET/PATCH/DELETE
  • /api/admin/appointment GET/PATCH/DELETE
